# Security Policy

FoxyFurniture is a personal project maintained by one person. This policy
explains how to report possible security vulnerabilities in the website or
repository code privately.

## Supported Versions

Security fixes are applied to the current website and latest repository code.
Older releases are not maintained separately.

## Reporting a Vulnerability

Please use GitHub's
[private vulnerability reporting form](https://github.com/kgomara/FoxyFurniture/security/advisories/new).
You will need to sign in to GitHub. You do not need repository write access or
the maintainer's email address to submit a report.

Please do not open a public issue or post exploit details in public comments.
Keep the discussion in the private report while the concern is assessed, and
discuss any public disclosure timing there.

### What to Include

- A short description of the suspected vulnerability and its security impact.
- The affected page URL, repository file, or component, with a version or
  revision date if known.
- Clear steps to reproduce the problem, including any necessary conditions.
- What you expected to happen and what actually happened.
- Screenshots or a minimal example if they help explain the problem. Redact
  passwords, tokens, personal information, and other sensitive data.

Reports do not need to be polished. Specific, reproducible details are more
useful than a severity label alone.

## Safe Reporting

Please do not access other people's accounts or data, change or delete data,
or disrupt the website while investigating a concern. Use your own test data
where possible and avoid destructive testing.

Submitting a report does not grant permission to change the repository.

## What to Expect

Good-faith reports will be reviewed as time permits. This is not a staffed
security service, so there is no guaranteed response time or fix date. Reports
may require clarification, and not every reported concern will result in a
change.

There is no bug-bounty program, and no payments or rewards are offered for
reports. Submitting a report does not require payment, installing software,
authorizing applications, or sending passwords or tokens to the maintainer.

Thank you for helping keep the project safe.
